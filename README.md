# CUK ACTION

최종 제출본을 기반으로 확장한 React + Vite 웹입니다. 기존 학생 화면의 디자인과 기능을 유지하고 계정 진입, 담당 공고 관리, Supabase 연결 코드를 추가했습니다.

## 현재 운영 상태

사용자의 요청에 따라 **UI와 테스트 데이터를 먼저 완성한 단계**입니다. 실제 Supabase 프로젝트는 아직 연결하지 않았습니다. 실제 회원가입과 로그인 버튼은 연결 전까지 비활성화됩니다. 테스트 공간을 실제 인증이나 서버 권한 통제로 표시하지 않습니다.

배포 주소: https://cuk-action.netlify.app

기존 Sites 프로젝트 ID와 소유자만 접근 가능한 비공개 범위를 유지합니다. 일반 학생이 배포 주소에 방문할 수 있도록 공개 범위를 바꾸지는 않았습니다.

## 실행과 테스트 진입

```powershell
npm install
npm run dev
```

체험 계정은 개발 서버(`npm run dev`)와 검사용 빌드(`npm run build:check`)에만 있습니다. 배포 빌드(`npm run build`)에는 체험 계정과 시연 데이터가 들어가지 않습니다.

`/account.html`에서 **학생 A로 체험** 또는 **담당자 A로 체험**을 누릅니다. 학생 A/B와 담당자 A/B를 각각 사용할 수 있습니다. 테스트 종료 후 다른 계정으로 들어가면 각자의 화면을 확인할 수 있습니다. 테스트 데이터는 이 브라우저의 `cuk-action-test-v2`에 저장됩니다. 같은 탭에서 새로고침해도 테스트 계정이 유지됩니다. 개인정보는 입력하지 마세요.

기존 `cuk-action-v1` 체험 데이터는 그대로 남겨 둡니다. 다른 계정의 서버 데이터로 자동 이전하지 않습니다.

## 학생 기능

- 학생용 회원가입과 로그인 화면, 계정 종료, 프로필 수정
- 계정별 프로필, 관심 공고, 직접 작성한 지원서, 준비 상태
- 미입력과 직접 확인 조건은 확인 필요로 표시하는 규칙 판정
- 직접 작성, 자동저장, 저장 실패 표시와 재시도, TXT 다운로드
- 체크리스트, 내 신청, 제출 완료 자기보고와 취소, 후속 절차 확인
- 준비 중인 공고가 게시 종료되어도 저장된 문항과 작성 내용 유지
- 실제 수집 공고 검색, 공식 원문 이동, 관심 등록
- 서비스 내 알림과 모바일 화면

학생 정보를 이용해 지원서를 생성하거나 AI로 전송하지 않습니다. 자격 조건과 준비율을 구분하며 조건 충족이 최종 선발을 보장하지 않습니다.

## 담당자 기능

- 담당자 전용 진입과 통합 대시보드
- 기간별 핵심 수치, 일별 그래프, 마감 일정, 공고 비교표
- 핵심 수치 선택 → 공고별 비교 → 공고 수정 → 같은 집계로 복귀
- 수정 후 집계 출처/기간/정렬/선택 공고와 위치 유지
- 가상 시나리오와 이 브라우저 기록의 분리
- 담당 공고 검색, 상태/분류 필터, 정렬
- 편집 단계 바로가기, 고정 저장 버튼, 게시 내림 확인
- 등록, 수정, 임시저장, 검수 후 게시, 게시 종료
- 원문, 신청 경로, 신청 안내, 마감과 근거 관리
- 지원 조건별 규칙과 근거, 제출 항목, 작성 문항, 후속 절차 관리
- 실제 공고 검수 초안 불러오기
- 담당 공고별 집계 기간과 분모, 조회/관심/준비/자기보고/링크 이동
- 학생별 명단과 지원서 본문을 제공하지 않는 집계
- 1~4명 비공개, 공식 접수 미연동, 행동으로 이탈 원인 단정 금지

현재 테스트 역할은 UI 검증용입니다. 실제 담당자 권한은 추후 연결할 PostgreSQL의 `manager_grants`와 RLS로 통제합니다. 학생 가입이나 화면 역할 선택으로 실제 권한을 얻을 수 없습니다.

## Supabase 연결 준비

Auth 클라이언트, PostgreSQL 스키마, RLS, 공고 검수와 집계 RPC를 구현했습니다. [SUPABASE.md](docs/SUPABASE.md)에 마이그레이션 적용, 공개키 설정, 담당자 권한 부여/회수/이관 SQL이 있습니다.

Vite 정적 화면이 Supabase Auth와 Data API에 연결하므로 기존 Sites 정적 배포를 유지합니다. 사용자 권한은 UI가 아니라 DB에서 검사합니다. 프런트엔드에는 공개 URL과 publishable key만 설정합니다. 관리자 비밀키는 사용하지 않습니다.

## 검증

```powershell
npm test
npm run test:db
npm run build
# 개발 서버를 실행한 상태에서 Python Playwright와 Edge 사용
npm run test:browser
# 검사용 빌드를 띄운 상태에서 공개 안내와 일정 확인 흐름 검사
npm run build:check
npm run preview:check
python scripts/check_guides.py
python scripts/check_schedule_reads.py
```

`npm run test:source`는 저장소에 포함하지 않은 원본 검수 자료가 있을 때만 실행합니다.

규칙/테스트 데이터 12개와 PostgreSQL RLS 22개 검증 그룹을 통과했습니다. 학생과 담당자 브라우저 흐름, 저장 실패, 저장 중 입력/종료, 모바일을 검증했습니다. 범위와 한계는 [VERIFICATION.md](docs/VERIFICATION.md)에 있습니다.

## 외부 연결 없는 신청 흐름 확장

실제 저장 공고에 근거한 테스트 초안 4건과 가상 학생 프로필 8종을 추가했습니다. 담당자가 초안을 불러와 검수 후 게시하면 학생이 체험할 수 있습니다. 날짜와 신청 경로는 가상입니다.

기수별 준비 상태, 한국 시간 마감, 공고 변경 확인, 선행 단계가 있는 후속 절차, 기수별 집계와 현재 후속 자기보고를 지원합니다. 기존 테스트 데이터는 자동으로 덮어쓰지 않습니다. 테스트 신청 경로는 외부로 이동하지 않습니다.

`npm test`는 25개이며 `npm run test:browser`에 전체 흐름 검사를 포함했습니다. 신규 집계는 브라우저 테스트 공간에서만 제공합니다.
