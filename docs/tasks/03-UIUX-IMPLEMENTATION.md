# 작업 3: 디자인 시스템 적용과 UI/UX 개선

상태: 미착수

## 목표와 시작 조건

작업 2의 디자인 시스템과 사용자 흐름을 실제 React 화면에 적용합니다. 학생과 담당자가 다음 행동을 쉽게 찾고 작업을 안전하게 이어갈 수 있도록 개선합니다.

시작 조건: 작업 1의 기능 변경과 데이터 형식이 정리되고 작업 2의 설계 산출물이 있어야 합니다. 산출물이 없다면 기존 화면 점검과 컴포넌트 목록 정리는 진행할 수 있습니다. 임의의 새로운 디자인 시스템을 만들어 덮어쓰지 않습니다.

## 적용 순서

1. 착수 시 화면과 검증 기준을 기록합니다. 다른 세션의 미완료 수정을 확인합니다.
2. 토큰과 반복되는 기본 컴포넌트부터 적용합니다. 한 번만 쓰는 요소를 무조건 공통 컴포넌트로 만들지 않습니다.
3. 학생의 공고 상세와 준비 화면 한 곳을 먼저 완성합니다. 읽기, 기수 선택, 직접 작성, 저장, 변경 확인, 자기보고, 후속 절차를 실제로 조작합니다.
4. 학생 홈, 탐색, 관심 목록, 내 신청, 알림, 프로필로 확장합니다. 홈에서 지금 해야 할 일을 찾을 수 있어야 합니다.
5. 담당자의 통합 현황, 비교표, 공고 목록, 편집과 검수로 확장합니다. 목록과 집계에서 수정으로 이동한 뒤 원래 작업 위치로 돌아오는 흐름을 유지합니다.
6. 모바일, 키보드, 빈 상태, 실패, 재시도, 저장 중 상태를 검사하고 수정합니다.
7. Before/After와 검증 기록을 남깁니다. 새 외부 연결이나 배포 없이 로컬 결과를 제공합니다.

## 개선할 사용성

- 긴 공고 편집에서 현재 위치와 저장 상태 확인
- 주된 행동과 보조 행동의 구분
- 조건 판정, 준비율, 마감, 후속 절차의 정보 위계
- 목록과 표의 밀도, 정렬, 검색, 필터, 상태 표시
- 공고 변경 전후의 차이와 기존 작성본 보존 안내
- 마감 시각 미확인과 자료 충돌의 명확한 표시
- 모바일 표의 스크롤 가능 표시와 작은 화면의 작업 버튼
- 오류가 발생한 입력란, 원인, 복구 행동의 연결
- 이전 화면 복귀 시 검색, 기간, 정렬, 선택 항목, 스크롤 보존

## 반드시 보존할 동작

- 학생과 담당자 역할의 구분
- 학생별 작성본과 상태 분리
- 기수별 독립 준비와 공고 전체 고유 인원 집계
- 링크 이동, 제출 자기보고, 공식 접수의 구분
- 미입력과 판정 불가능 조건의 확인 필요 표시
- 저장 실패 시 입력 보존과 재시도
- 저장 중 마지막 입력 보존
- 변경 확인 전 완료 표시 제한
- 게시 종료와 기수 삭제 후 작성본 보존
- 후속 단계의 선행 조건과 취소 처리
- 담당자 집계의 본문 비공개와 소수 인원 비공개
- 테스트 신청 경로의 외부 이동 차단

## 담당 범위

주요 파일: `src`의 React 컴포넌트와 CSS, 필요한 UI 테스트. 업무 규칙과 데이터 형식은 작업 1의 결과를 따릅니다. 불가피한 로직 변경은 재현 사례와 검사를 함께 남깁니다.

외부 인증과 DB 연결, AI, 카카오, 학교 시스템은 추가하지 않습니다. 새 라이브러리는 작업 2의 근거와 현재 코드에 맞는 최소 범위로 도입합니다. 설치가 필요하더라도 런타임 CDN이나 외부 글꼴 호출을 추가하지 않습니다.

## 검증과 완료 기준

- `npm test`, `npm run test:db`, `npm run build` 통과
- 로컬 서버에서 `npm run test:browser` 통과
- UI 변경에 맞는 시나리오 추가. 기존 검사 의미와 실패 조건 유지
- 390px와 1440px에서 학생과 담당자 핵심 경로 직접 조작
- 키보드만으로 진입, 공고 선택, 작성, 저장, 복귀 확인
- 대비와 초점 표시, 입력 오류 안내 확인
- 외부 요청과 런타임 오류 확인
- 디자인 토큰과 실제 적용의 불일치 점검
- 변경 이유와 전후 화면, 알려진 한계 기록

새 디자인이 보기 좋다는 설명만으로 완료하지 않습니다. 사용자가 필요한 정보를 찾고 작업을 마칠 수 있는지를 확인합니다. 자동 검사 결과를 실제 학생의 만족도나 성과로 바꿔 말하지 않습니다.
