# 작업 1: 핵심 기능과 실제 공고 검증

상태: 자동 기능 검증 완료. 실제 학생 실험 미실시.

## 목표

외부 서비스 연결 없이 실제 공고 검수와 조건 비교의 정확도를 높입니다. 학생 준비부터 담당자 집계까지 실제 사례를 넣어 검증합니다. 화면 전면 개편은 작업 3이 맡습니다.

## 수행 작업

1. 유형이 다른 실제 공고 10~15건을 선정합니다. 간단한 폼, 직접 작성, 학년별 조건, 복수 기수, 기숙사 후속 절차, 자료 불일치를 포함합니다. 건수를 채우기 위해 근거 없는 항목을 만들지 않습니다.
2. 저장 본문과 이미지, 확보된 첨부를 대조합니다. 항목마다 원문 위치와 확인 범위, 미확인 사유를 기록합니다. 첨부가 없거나 해독하지 못하면 해당 조건과 문항을 확정하지 않습니다.
3. 실제 공고 정답셋과 가상 시연 데이터를 분리합니다. 시연을 위해 날짜를 옮기면 원래 날짜와 가상 날짜를 함께 기록합니다. 마감한 실제 공고를 현재 모집 중으로 표시하지 않습니다.
4. 가상 학생 8개 유형과 공고별 기대 결과를 정의합니다. 충족, 미충족, 확인 필요를 구분합니다. 학점 3.0 경계값, 학점 미입력, 휴학, 선택 항목별 제한을 포함합니다.
5. 정답셋에서 드러난 조건 처리의 부족분만 구현합니다. 예: 학년과 학기에 따라 선택 가능한 과목이 달라지는 경우. 조건 전체를 범용 규칙 엔진으로 바꾸지 말고 실제 사례에 필요한 최소 표현을 선택합니다.
6. 변경과 실패 상황을 검증합니다. 마감 연장, 필수 서류 추가, 기수 삭제, 준비 중 게시 종료, 저장 실패, 후속 단계 취소를 포함합니다.
7. 원문만 보는 방식과 서비스 사용 방식을 비교할 사용자 과제와 기록지를 만듭니다. 정답률, 소요시간, 누락 수를 측정할 수 있게 합니다. 과제 순서와 공고를 나눠 학습 효과를 줄입니다. 실제 참가자를 모집하거나 임의의 효과 수치를 만들지 않습니다.

## 담당 범위

주요 파일: `src/logic.js`, `src/workflow.js`, 공고 데이터 파일, `src/gateway.js`, 관련 테스트. 새 입력이 필요한 경우 `main.jsx`와 `Manager.jsx`는 최소 수정만 합니다.

작업 2의 디자인 문서와 미리보기는 수정하지 않습니다. 데이터 형식을 바꿨다면 작업 3을 위한 이전 방식과 보존 규칙을 기록합니다.
