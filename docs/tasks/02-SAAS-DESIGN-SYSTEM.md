# 작업 2: SaaS 조사와 디자인 시스템 설계

상태: 시각 디자인 재검토 / 기존 After 적용 보류

## 목표

실제로 운영하는 SaaS처럼 정보를 배치하고 작업을 이어갈 수 있는 디자인 기준을 만듭니다. GitHub UI 프로젝트와 실제 제품 화면을 조사해 CUK ACTION에 맞는 기준을 선택합니다. 제품 코드 적용은 작업 3이 맡습니다.

- `docs/NEXT-STEPS-2026-11-11.md`
- `docs/OFFLINE-WORKFLOW.md`, `docs/UX-REVIEW.md`, `docs/SAAS-REFERENCES.md`
- `_ref/간격카드_2026-11-10.md`

- 로컬 학생과 담당자 화면. 화면 캡처만 보지 말고 실제 조작도 확인

## 리서치

1. GitHub 프로젝트와 공식 문서를 4~6개 비교합니다. shadcn/ui, Radix, MUI, Ant Design, Mantine은 조사 출발점입니다. 이 목록은 채택 결정이나 최신 인기 순위가 아닙니다.
2. 조사 시점의 라이선스, 유지보수 상태, 접근성, 컴포넌트 범위, React 호환성, 의존성, 도입 비용을 확인합니다. 저장소 URL과 확인일을 남깁니다. 별 수만으로 선택하지 않습니다.
3. 컴포넌트 라이브러리와 완성된 SaaS의 사용자 흐름을 별도로 조사합니다. 라이브러리 데모를 실제 제품의 전체 사용 흐름으로 간주하지 않습니다.
4. 학생의 신청 준비와 담당자의 공고 운영에 가까운 실제 제품 화면을 3개 이상 확인합니다. 기존 Submittable, Airtable, SurveyMonkey Apply 조사도 출발점으로 재검토합니다. 로그인 벽은 우회하지 않습니다.
5. 각 패턴의 출처와 적용 이유를 남깁니다. 색과 글꼴을 여러 제품에서 무작위로 섞지 않습니다. 유료 템플릿이나 라이선스가 불명확한 코드는 복제하지 않습니다.

## 설계

학생 흐름: 진입 → 공고 탐색 → 조건 확인 → 기수 선택 → 준비 → 자기보고 → 후속 절차.

담당자 흐름: 현황 확인 → 공고 비교 → 수정 또는 검수 → 게시 → 같은 집계로 복귀.

각 화면에 목적, 가장 중요한 행동, 필수 정보, 접을 정보, 이전 화면으로 돌아갈 때 유지할 상태를 적습니다. 카드 수를 줄이는 것 자체를 목표로 삼지 않습니다. 표, 행 목록, 상세 패널, 단계 입력을 업무에 맞게 선택합니다.

디자인 시스템에는 다음 항목을 포함합니다.

- 브랜드와 의미별 색, 대비 기준
- 한글 타이포그래피와 숫자 표시
- 간격, 콘텐츠 폭, 레이아웃, 반응형 기준
- 경계선, 모서리, 그림자, 아이콘, 동작 줄이기
- 버튼, 입력, 선택, 날짜와 시각 입력, 탭, 배지
- 목록, 비교표, 공고 상세, 체크리스트, 단계별 후속 절차
- 로딩, 빈 화면, 실패, 재시도, 저장 중, 저장 완료, 변경 알림
- 키보드 이동, 초점 표시, 오류와 입력란 연결

기존 브랜드색과 정보 의미를 우선 보존합니다. 바꿀 이유가 있다면 현재 값과 제안 값을 비교합니다. UI 라이브러리는 하나의 주된 기준을 선택하고 추가 라이브러리는 필요한 이유를 적습니다. 기존 코드로 충분하다면 패키지 도입 없이 기준만 채택할 수 있습니다.

## 산출물

- `docs/design/RESEARCH.md`: 출처, 확인일, 후보 비교, 채택과 제외 이유
- `docs/design/DESIGN-SYSTEM.md`: 토큰과 컴포넌트 규격의 정본
- `docs/design/USER-FLOWS.md`: 학생과 담당자 흐름, 화면별 목적, 상태 전환
- `docs/design/COMPONENT-MAP.md`: 기존 구현 있음/일부/신규와 대상 파일
- `_ref/uiux-2026-11-11/preview.html`: 대표 화면 Before/After와 컴포넌트 상태를 보여 주는 로컬 미리보기
- `docs/design/IMPLEMENTATION-PLAN.md`: 작업 3의 파일별 적용 순서와 검증 기준

미리보기는 최소 학생 홈, 신청 준비 상세, 담당자 공고 목록 또는 집계를 포함합니다. 데스크톱과 모바일을 확인합니다. 외부 글꼴이나 CDN 없이 로컬에서 열 수 있게 만듭니다. 핵심 대비와 간격의 측정값을 남깁니다.

## 담당 범위와 완료 기준

수정 범위: `docs/design/`와 `_ref/uiux-2026-11-11/`. 제품 `src`와 DB, 기존 테스트 데이터는 수정하지 않습니다.

완료 기준: 실제 출처를 확인한 비교 자료, 하나로 정리한 디자인 정본, 화면별 행동 우선순위, 렌더링한 대표 화면, 기존 컴포넌트 재사용 계획, 작업 3이 바로 적용할 수 있는 실행안. 말로만 설명한 디자인은 완료가 아닙니다.

실제 선택이 필요한 대안은 비교 가능한 미리보기까지 만든 뒤 제시합니다. 아직 조사하지 않은 내용을 이미 검증한 레퍼런스로 표현하지 않습니다.
