# 화면 이동 규칙

로그인 앱(학생·담당자)과 공개 페이지가 따르는 규칙이다. 새 화면을 만들 때도 이 규칙을 따른다.

## 1. 화면은 두 층이다

- **목록 화면**: 사이드바 메뉴로 가는 화면이다. 학생은 홈, 공고 탐색, 관심 공고, 내 신청, 알림이다. 담당자는 담당자 대시보드, 공고 관리, 담당자 설정이다.
- **상세 화면**: 목록에서 항목 하나를 연 화면이다. 학생 공고 상세, 보관함 공고 상세, 공고 작성(편집기), 공고 집계가 해당한다.

## 2. 상세 화면 머리는 한 가지 모양이다

위에서 아래 순서로 놓는다.

1. 뒤로가기 버튼 (`← 공고 탐색으로`)
2. 분류 태그나 eyebrow (있을 때만)
3. 제목 `h1` 하나
4. 주요 버튼은 제목 줄 오른쪽 (좁은 화면에서는 제목 아래)

상세 화면에서는 목록 화면의 머리(페이지 제목, 안내문, 계정 띠)를 숨긴다. 한 화면에 `h1`은 하나다.

## 3. 뒤로가기는 들어온 곳으로 간다

- 고정된 곳으로 보내지 않는다. 대시보드에서 연 집계는 대시보드로, 공고 관리에서 연 집계는 공고 관리로 돌아간다.
- 상세에서 다른 상세로 이어 가면 직전 상세로 돌아간다. 예: 공고 집계 → 공고 수정 → 뒤로 → 공고 집계 → 뒤로 → 들어온 목록.
- 문구는 `{돌아갈 화면 이름}으로/로`다. "돌아가기"를 붙이지 않는다. 예: `홈으로`, `공고 탐색으로`, `담당자 대시보드로`, `공고 관리로`, `공고 집계로`.
- 같은 화면은 어디서나 같은 이름을 쓴다. 담당자의 공고별 수치 화면 이름은 **공고 집계**다.

## 4. 돌아오면 목록 상태가 그대로다

검색어, 필터, 정렬, 페이지 번호, 집계 기간, 스크롤 위치를 유지한다. 방금 연 항목에 포커스를 돌려준다.

## 5. 기기 뒤로가기는 화면 뒤로가기 버튼과 같다

- 상세 화면은 `src/back-layer.js`의 `useBackLayer(active, onBack)`를 쓴다. 열릴 때 브라우저 기록 한 칸을 쌓는다.
- 화면 안 뒤로가기 버튼은 `goBack()`을 부른다. 실제 이동은 `onBack`이 한다. 그래서 두 버튼이 같은 길을 탄다.
- `onBack`은 화면을 닫거나 `false`를 돌려준다. 저장하지 않은 수정이 있어 사용자가 취소하면 `false`를 돌려주고 그 화면에 남는다.
- 사이드바 메뉴처럼 다른 길로 상세를 닫으면 `useBackLayer`가 쌓아 둔 기록을 알아서 지운다.

## 6. 지금 위치는 사이드바와 뒤로가기 버튼으로 보여 준다

- 위쪽 위치 표시 막대(breadcrumb)는 쓰지 않는다. 휴대폰에서는 위쪽에 메뉴 버튼만 둔다.
- 사이드바의 활성 메뉴는 들어온 목록이다. 상세 화면에서도 들어온 목록이 활성으로 남는다.
- 상세 화면의 위치는 뒤로가기 버튼 문구(`← 공고 탐색으로`)가 알려 준다.
- 사이드바 로고는 공개 홈페이지(`/`)로 간다.
