# 정보 위계 체계

모든 화면(공개 홈, 학생, 담당자, 로그인)은 이 규칙을 따른다. 새 화면을 만들거나 고칠 때 먼저 읽는다. 색과 간격 토큰은 [디자인 시스템](DESIGN-SYSTEM.md), 화면 이동은 [NAVIGATION.md](NAVIGATION.md)를 따른다. 부품 모양은 [부품 목록](catalog.html)에서 본다(`npm run dev` 뒤 `/docs/design/catalog.html`).

작성: 2026-11-26. 근거: 현재 화면 26장 캡처(`_ref/hierarchy-2026-11-26/before/`)와 국내 취업·금융 앱 6개의 앱스토어 화면 30장(`_ref/hierarchy-2026-11-26/refs/`).

## 1. 왜 정했나

2026-11-26 실측에서 이렇게 나왔다.

- CSS에 글자 크기가 26종, 글자색이 28종 있었다. 9~11px 글자가 144곳이었다.
- 상태(조건 충족), 속성(부서), 출처(테스트 게시 공고)가 같은 회색 칩 모양이었다. 버튼과도 구별되지 않았다.
- 회색 글자 링크("학교 원문 보기")와 파란 배지("마감일 없음")가 섞여, 누를 수 있는 것을 모양으로 알 수 없었다.
- 같은 공고 카드가 8개 이어지고 카드마다 진한 파란 버튼이 있었다. 담당자 공고 관리 한 화면에 주 버튼이 9개였다.

레퍼런스(자소설닷컴, 캐치, 원티드, 링커리어, 사람인, 토스)는 모두 같은 방식을 쓴다. 목록은 구분선 행으로 놓는다. 상태는 테두리 없는 색 글자로 쓴다. 누르는 것은 버튼과 `›`가 붙은 글자뿐이다.

## 2. 요소 역할 5가지

화면의 모든 요소는 아래 다섯 가지 중 하나다. 역할마다 모양을 하나만 쓴다. 한 모양을 두 역할에 쓰지 않는다.

| 역할 | 뜻 | 모양 | 예 |
|---|---|---|---|
| 행동 | 누르면 화면이나 데이터가 바뀐다 | 주 버튼(파란 채움), 보조 버튼(흰 바탕, 회색 테두리, 파란 글자), 글자 링크(파란 굵은 글자 + `›` 또는 `↗`), 아이콘 버튼(44px, 이름 필수) | 신청하기, 공고 수정, 학교 원문 보기 ↗, 관심 등록 |
| 선택 | 보는 범위나 입력값을 고른다 | 탭, 분류 버튼(선택 시 남색 채움), 체크박스, 셀렉트, 입력칸 | 분류 탭, 마감 전 공고만, 정렬 |
| 상태 | 공고나 내 진행이 지금 어떤지. 시간이나 행동에 따라 바뀐다 | `.tag` 배지(테두리 없음, 4px 모서리, 옅은 바탕) 또는 아이콘 + 색 글자. 누를 수 없다 | 조건 충족, 확인 필요, D-3, 게시 중, 임시저장 |
| 속성 | 공고의 바뀌지 않는 정보 | `.meta-line` 회색 보조 글자를 `·`로 잇는다. 칩, 테두리, 바탕을 쓰지 않는다 | 취업지원팀 · 진로 · 외부 신청 · 게시일 11.16 |
| 안내 | 사용자에게 하는 설명 | 안내 박스(정보 파랑, 주의 주황, 오류 빨강) 또는 도움말(입력이나 버튼 바로 아래 보조 글자) | 조건 충족은 선발을 보장하지 않습니다 |

다섯 가지로 정한 이유:

- 이 서비스는 판정과 진행 값이 많다. 조건 충족, 준비 완료, 경로 이동, 제출 표시, 공식 접수는 서로 다른 값이다([디자인 시스템](DESIGN-SYSTEM.md) 의미 보존 규칙). 그래서 상태를 속성과 떼어 따로 보이게 한다.
- 공고에는 부서, 분류, 신청 방식, 게시일 같은 고정 정보가 많다. 이것을 칩으로 만들면 상태와 섞인다. 그래서 속성은 가장 조용한 모양을 쓴다.
- AI 정리와 원문 확인 안내가 많다. 안내를 상태나 본문과 섞지 않게 따로 둔다.
- 선택은 행동과 다르다. 눌러도 화면을 떠나지 않고 보는 범위만 바뀐다.

지킬 것:

- 파란 글자는 항상 누를 수 있다. 누를 수 없는 것에 파란 글자를 쓰지 않는다. 회색 글자는 누를 수 없다.
- 예외 하나: 목록 행의 제목은 검은 글자여도 누를 수 있다. 마우스를 올리면 밑줄이나 행 배경으로 알린다.
- 주 버튼은 카드 하나에 하나까지, 화면 전체에서도 원칙적으로 하나다. 목록의 각 행에는 주 버튼을 두지 않는다.
- 상태 색은 뜻이 하나다. 초록 = 충족·완료, 주황 = 확인 필요, 빨강 = 오류·마감·조건 미충족, 파랑 = 진행 중·정보, 회색 = 중립·종료. 파랑 배지는 옅은 파란 바탕에 진한 남색 글자를 쓴다. 파란 글자는 누를 수 있는 것에만 쓰기 때문이다.
- 상태는 색만으로 알리지 않는다. 문구나 아이콘을 함께 쓴다.
- 같은 안내는 한 화면에 한 번만 쓴다. 안내 박스는 카드 하나에 하나까지다.
- 데이터 출처(테스트 게시 공고, 검수된 실제 공고)는 탭이나 화면 제목이 이미 알려 주면 목록 행에서 다시 쓰지 않는다. 상세에서는 속성 줄에 쓴다.
- 영문 소제목(eyebrow, `CAMPUS NOTICES` 등)은 쓰지 않는다. 화면 제목과 같은 말을 되풀이한다.

## 3. 글자 6단계

| 단계 | 토큰 | 크기(휴대폰) | 굵기 | 색 | 쓰는 곳 |
|---|---|---|---|---|---|
| 숫자 | `--fs-num` | 28px(24) | 700 | ink | 집계 숫자, 건수 강조 |
| 화면 제목 | `--fs-h1` | 26px(22) | 700 | ink | 화면당 하나 |
| 섹션 제목 | `--fs-h2` | 18px | 700 | ink | 카드 제목, 섹션 제목 |
| 항목 제목 | `--fs-h3` | 15px | 600 | ink | 공고 제목, 목록 행 제목, 조건 이름 |
| 본문 | `--fs-body` | 14px | 400 | ink | 설명, 입력, 버튼, 글자 링크 |
| 보조 | `--fs-small` | 12px | 400~600 | muted `#56647a` | 속성, 도움말, 배지, 표 머리, 안내 박스 |

여섯 단계로 정한 이유: 담당자 화면에는 집계 숫자가 있고, 학생 화면에는 공고 제목 목록이 있다. 숫자와 항목 제목을 다른 단계와 섞으면 핵심이 묻힌다. 나머지는 제목 두 단계, 본문, 보조로 충분하다.

지킬 것:

- CSS에 글자 크기를 숫자로 쓰지 않는다. `var(--fs-*)`만 쓴다. 예외는 로고와 장식 그림 글자다.
- 12px보다 작은 글자를 쓰지 않는다. 로고 아래 작은 글자만 예외다.
- 이웃한 단계는 크기, 굵기, 색 중 둘 이상이 다르다.
- 가장 큰 글자와 강조색은 블록 하나에 한 덩어리만 준다.
- 검사: 화면에서 큰 글자만 이어 읽으면 그 화면의 할 일이 읽혀야 한다.

## 4. 카드와 간격

묶음은 카드와 간격을 함께 써서 보인다. 표면은 세 층이다.

| 층 | 모양 | 쓰는 곳 |
|---|---|---|
| 배경 | 회색 `--bg` | 화면 바탕. 화면 제목, 필터 줄은 카드 없이 배경 위에 둔다 |
| 카드 | 흰 바탕, `--line` 테두리, 16px 모서리, 그림자 없음 | 한 가지 일이나 한 대상을 묶는다 |
| 회색 면 | `.sub-surface` 회색 바탕, 12px 모서리 | 카드 안의 하위 묶음 |

카드를 쓰는 곳:

- 한 가지 일을 끝내는 단위. 지원 조건 확인, 체크리스트, 신청서, 집계 요약.
- 같은 종류 항목 목록 전체를 담는 그릇. 목록 카드 하나 안에 행을 구분선으로 나눈다.
- 사진이 핵심이거나 2~4개 중 하나를 고르는 선택지. 추천 공고, 공고 묶음.

카드를 쓰지 않는 곳:

- 목록의 각 행. 행은 구분선으로 나눈다. 같은 카드를 3개 넘게 이어 놓지 않는다.
- 카드 안에 다시 흰 카드를 넣지 않는다. 회색 면을 쓴다.
- 안내 박스는 카드가 아니다. 카드 안에 둔다.

카드 하나에는 제목(섹션 제목) 하나와 주 버튼 하나까지 둔다.

간격은 `--sp-*`만 쓴다.

| 자리 | 값 |
|---|---|
| 한 줄 안(아이콘과 글자, 배지 사이) | 8px `--sp-1` |
| 묶음 안 항목 사이, 카드 제목과 내용 사이 | 16px `--sp-2` |
| 카드 안쪽 여백 | 24px `--sp-3`, 휴대폰 16px |
| 카드와 카드 사이 | 16px `--sp-2` |
| 섹션 사이 | 32px `--sp-4` |

## 5. 화면별 최우선

| 화면 | 목적 | 최우선 하나 | 주 버튼 |
|---|---|---|---|
| 공개 홈 | 교내 공고를 찾는다 | 검색과 공고 목록 | 없음(로그인 버튼은 위쪽 막대) |
| 공개 공고 상세 | 이 공고가 무엇인지 보고 넘어간다 | 제목과 원문 | 학교 원문 보기 |
| 로그인 | 로그인한다 | 입력칸 | 로그인 |
| 학생 홈 | 이어서 할 일을 한다 | 오늘 이어서 할 일 | 이어서 할 일 버튼 |
| 공고 탐색, 관심 공고 | 맞는 공고를 고른다 | 공고 목록 | 없음 |
| 학생 공고 상세 | 지원할 수 있는지 보고 준비를 시작한다 | 지원 조건 판정 | 지원 준비 시작 또는 신청하기 |
| 내 신청, 알림 | 진행 중인 것을 이어 간다 | 목록 | 없음 |
| 담당자 대시보드 | 공고 반응을 보고 할 일을 찾는다 | 집계 숫자 | 새 공고 등록 |
| 공고 관리 | 공고를 찾아 고친다 | 공고 목록 | 공고 등록 |
| 공고 편집 | 공고를 쓰고 게시한다 | 입력 단계 | 게시 |

## 6. 고칠 때 확인할 것

1. 이 요소는 다섯 역할 중 무엇인가. 그 역할의 모양을 썼는가.
2. 파란 글자가 누를 수 없는 곳에 쓰였는가.
3. 카드 안 주 버튼이 둘 이상인가.
4. 같은 카드가 3개 넘게 이어지는가.
5. 같은 안내가 두 번 나오는가.
6. CSS에 숫자 글자 크기가 새로 생겼는가. `grep -o "font-size:[0-9.]*\(px\|rem\)" src/*.css`로 확인한다. 로고와 장식 글자(`.brand`, `.mini-brand`, `.art-star`, `.access-intro h1`)만 나와야 한다.
