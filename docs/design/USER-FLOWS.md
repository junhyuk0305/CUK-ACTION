# 화면 흐름과 상태 보존

작성일: 2026-11-11. 디자인 적용 대상이며 기능 추가 명세가 아니다. 최신 작업 1의 조건 규칙과 데이터 계약이 우선한다.

## 학생의 전체 경로

진입 → 홈/공고 탐색 → 조건 확인 → 기수 선택 → 준비 시작 → 직접 작성/체크리스트 → 공식 경로로 직접 제출 → 제출 완료 자기보고 → 후속 절차.

공식 경로는 외부 시스템이다. CUK는 실제 제출 성공을 확인하지 못한다. 테스트 경로에서는 외부 이동도 차단한다.

| 화면 | 목적 / 가장 중요한 행동 | 필수 정보 | 접을 정보 | 복귀 시 유지 |
|---|---|---|---|---|
| 진입 | 역할 확인 / 테스트 계정 진입 | 가상 계정, 로컬 저장, 미연동 범위 | 실제 인증 폼 미리보기 | 세션 계정 복원. 종료 시 계정 기억 제거 |
| 홈: 신규 | 시작점 제공 / 공고 탐색 | 공고 출처, 마감, 미입력 조건의 확인 필요 | 긴 소개, 묶음 설명 | 탐색 검색과 스크롤 |
| 홈: 준비 중 | 작업 재개 / 이어서 준비 | 대표 공고, 선택 기수, 남은 항목, 마감 경고 | 전체 신청 현황 세부 | application id, 준비 탭 |
| 홈: 자기보고 후 | 남은 절차 안내 / 후속 절차 확인 | 다음 단계, 기한, 선행 조건 | 완료된 단계 근거 | 단계 완료 표시 |
| 공고 탐색 | 비교 / 조건 확인 | 제목, 부서, 분류, 출처, 마감, 조건 요약, 관심 여부 | 상황별 묶음 설명, 과거 보관함 안내 | query/category/bundle/sort/openOnly/dataset/스크롤 |
| 관심 공고 | 보관한 공고 재확인 / 상세 열기 | 실제 수집과 검수된 공고 구분, 검색 결과 건수 | 긴 본문 | 검색, 원래 관심 목록, 스크롤 |
| 공고 상세: 조건 | 가능/미확인 구분 / 준비 시작 | 조건별 결과, 근거, 일정 불일치, 기수별 조건 | 원문 긴 인용 | notice id, option id, 탭, 목록 복귀 위치 |
| 기수 선택 | 대상 확정 / 선택 항목으로 준비 | 각 기수의 마감, 경로, 상태 | 기수 설명의 세부 근거 | 기존 기수별 application key. 다른 기수에 복사하지 않음 |
| 직접 작성 | 본인이 작성 / 다음 준비 확인 | 실제 검수 문항, 글자수, 저장 상태, 다운로드 | 작성 도움말의 상세 | 문항별 answers, 마지막 입력, 기수, 저장 오류 |
| 제출 준비 | 누락 확인 / 실제 제출 후 자기보고 | 항목 완료수, 변경 확인, 신청 경로, 미연동 안내 | 완료 항목의 상세 근거 | checks, reviewedRequirements, completed |
| 후속 절차 | 신청 후 누락 방지 / 가능한 다음 단계 확인 | 기한, 근거, 선행 조건, 완료수, 자기보고 | 완료된 단계의 긴 설명 | followupChecks, 완료 취소 연쇄 |
| 내 신청 | 진행 신청 선택 / 이어서 준비 또는 후속 확인 | 준비/자기보고 구분, 게시 종료 보관본, 기수 | 긴 공고 요약 | applicationFilter와 스크롤 |
| 알림 | 바뀐 점 확인 / 해당 신청 열기 | 변경/마감/후속 구분, 읽음 상태, 발송 미연동 | 기존에 읽은 안내 | alarmKey별 읽음. 새로운 변경은 새 알림 |
| 프로필 | 비교 정보 수정 / 저장 | 모르면 비움, 가상 정보 안내, 필드 오류 | 테스트 프로필 채우기 | 저장 전 로컬 편집, 닫기 뒤 호출 버튼 초점 |
| 실제 공고 보관함 | 원문 재확인 / 본문 또는 공식 원문 | 수집 날짜, 미검수, 과거 여부, 첨부 미확인 | 첨부 목록 세부 | query, limit, 선택 item, 복귀 출처 |

홈 선택 우선순위: 변경 확인이 필요한 진행 신청 → 기한이 가까운 실행 가능한 후속 단계 → 마감이 가까운 준비 중 신청 → 신규 탐색. 동률이면 기존 정렬을 유지한다. 첫 화면에 모든 알림을 카드로 펼치지 않는다. 대표 1개와 전체 내 신청 접근을 제공한다. 이 우선순위는 작업 3에서 기존 데이터만으로 계산하며 상태를 새로 저장하지 않는다.

## 학생 상태 전환

| 현재 / 이벤트 | 다음 상태 | 반드시 지킬 조건 |
|---|---|---|
| 상세 열기 | 열람 상태 | 준비 시작 이벤트 자동 발생 금지 |
| 준비 시작 클릭 | 준비 중 | 마감 종료 규칙 검사. 조건 미확인과 지원 불가 판정을 UI에서 덮어쓰지 않음 |
| 기수 변경 | 선택 기수의 준비 상태 | 다른 기수의 답변/체크 유지. 렌더 key를 공고 제목으로 만들지 않음 |
| 입력 | pending → saving → saved/error | 마지막 입력 보존. saved는 저장 계층 확인 뒤 표시 |
| 요구사항 변경 | 변경 확인 필요 | 기존 작성본/체크 보존. 새 문항 자동 삽입 금지 |
| 최신 내용 확인 | 자기보고 재검사 가능 | reviewedRequirements를 최신 requirementsKey와 비교 |
| 체크리스트 완료 | 준비 완료 | 자격 충족이나 공식 접수 완료로 전환하지 않음 |
| 신청 링크 클릭 | 경로 이동 기록 | completed 자동 설정 금지 |
| 자기보고 클릭 | 확인 대화상자 → 제출 자기보고 | 기존 canComplete 계열 규칙 통과, 변경 확인, 저장 성공 구분 |
| 자기보고 취소 | 준비 중 | 후속 단계 상태는 기존 업무 규칙에 따라 취소 |
| 후속 체크 | 해당 단계 자기보고 | step.ready, requires 준수. 기한 변경 시 재확인 |
| 선행 단계 취소 | 후속 완료 재계산 | 후행 체크를 그대로 성공 상태로 남기지 않음 |
| 게시 종료/옵션 삭제 | 보관본 | noticeSnapshot으로 기존 작성본 접근 보존 |

자기보고 확인창은 추가 안내를 위한 제안이다. 확인창을 통과해도 자격/마감/변경 검사를 우회하지 않는다. 미리보기는 일부 상태만 재현하므로 업무 규칙 구현으로 복사하지 않는다.

## 담당자의 전체 경로

통합 현황 → 기간과 출처 선택 → 공고 비교 → 선택 공고 수치 → 수정/검수 → 게시 또는 임시저장 → 같은 집계로 복귀.

공고 관리 → 검색/필터 → 수정 또는 집계 → 저장/취소 → 같은 목록으로 복귀.

| 화면 | 목적 / 가장 중요한 행동 | 필수 정보 | 접을 정보 | 복귀 시 유지 |
|---|---|---|---|---|
| 통합 현황 | 범위 파악 / 공고별 비교 | 기간, 출처, 담당 공고 범위, 고유 사용자, 공식 접수 미연동 | 상세 지표 정의 | source, period, preset, sort |
| 공고 비교 | 차이 확인 / 공고 선택 | 게시 상태, 마감, 지표 열, 비공개, 분모 | 세부 정의와 전체 원문 | selectedId, 정렬, scroll, 호출 버튼 |
| 선택 공고 상세 | 수치 확인 / 공고 수정 | 공고 제목, 동일 기간/출처, 분모, 5개 행동 지표 | 기수/후속 표는 섹션 분리 | selectedId와 집계 context |
| 공고 관리 목록 | 운영 대상 선택 / 수정 또는 집계 | 검색, 분류, 정렬, 게시 상태, 마감, 초안 가져오기 | 검수 초안 picker는 details | search/statusFilter/categoryFilter/sort/scroll |
| 공고 편집 | 내용 수정 / 검수 후 게시 | 현재 게시 상태, dirty/saving, 원문 근거, 오류, 검수 체크 | 단계 설명. 입력 자체는 임의로 숨기지 않음 | editing, taskText, editorOrigin, editorContext |
| 개별 집계 | 한 공고의 진행 확인 / 수정 | 기간, 분모, 행동 집계와 현재 후속 집계 분리 | 지표 정의 | metricNotice와 적용 기간 |

통합 현황의 그래프, 날짜별 표, 접근 가능한 날짜 선택은 기존 기능을 유지한다. 목록을 더 짧게 보이게 하려고 그래프의 대체 표나 비공개 안내를 제거하지 않는다.

## 검수와 복귀 계약

- 입력 변경 → reviewed=false. 게시 검수 체크를 자동 유지하지 않는다.
- 저장 중 → 중복 저장 차단, 이탈 제한. dirty 상태 이탈 → 기존 확인 유지.
- `게시 내리고 임시저장`은 학생 목록에서 숨김을 명시하고 확인창 유지.
- 게시 종료는 학생의 보관본을 삭제하지 않는다.
- 성공 메시지 후에는 현재 스크롤을 보존한다. 사용자가 복귀를 선택했을 때 원래 행과 초점으로 이동한다.
- 집계에서 수정한 경우 목록 기본 화면으로 보내지 않는다. 선택 기간, 출처, 정렬, 공고가 유지된 집계로 돌아간다.
- 기간을 변경하면 새 요청 중 상태와 적용된 기간을 구분한다. 늦게 도착한 이전 요청으로 덮어쓰지 않는다.
- 1~4명은 그래프 막대/tooltip/CSV 대체표에서도 비공개다. 다른 열의 차감으로 인원을 추정하도록 UI를 추가하지 않는다.

## 모바일과 실패 경로

모바일에서도 제목, 마감 경고, 선택 기수, 현재 행동 순서는 같다. 상세의 보조 요약은 본문 뒤로 이동한다. 담당자 비교표는 내부 스크롤과 안내를 제공한다. 수정 버튼은 선택 상세 안에 두어 오른쪽 끝 열을 찾아야만 수정할 수 있는 상황을 피한다.

필터 결과 없음은 초기화 행동을 제공한다. 서버 읽기 실패는 재시도로 복구한다. 저장 실패는 입력을 유지하고 retry와 다운로드를 제공한다. 새로고침으로 저장 실패를 해결하라는 안내를 기본으로 쓰지 않는다. 오류 summary에서 첫 오류 필드로 초점을 연결한다.

## 후속 사용자 검증 과제

아직 실제 학생/담당자 검증을 수행하지 않았다. 작업 3 이후 동일 데이터로 기존 UI와 개선 UI를 비교한다.

1. 학생: 조건이 미확인인 공고에서 필요한 확인 사항 찾기. 준비한 기수 재개. 자기보고와 공식 접수 차이 설명.
2. 학생: 마감 변경 확인 후 기존 작성본 찾기. 후속 선행 단계 취소 결과 이해.
3. 담당자: 7일 집계의 특정 공고 선택, 수정, 같은 집계 복귀. 1~4명 비공개의 의미 설명.
4. 측정: 첫 올바른 행동까지 시간, 잘못 누른 횟수, 누락 항목, 과제 완료 여부. 디자인 선호도는 별도 질문.

참여자 수와 합격 기준은 사용자 검증 담당이 정한다. 시안 스크린샷이나 자동 검사를 사용자 성과로 보고하지 않는다.
