# 학생과 담당자 UI 사용 검토

검토일: 2026-11-10. Edge에서 학생 A/B와 담당자 A/B로 직접 조작했습니다. 기존 디자인을 유지했습니다. Supabase는 연결하지 않았습니다.

| 사용 중 발견한 문제 | 수정 |
|---|---|
| 첫 화면에 사용할 수 없는 실제 로그인 폼이 먼저 보임 | 테스트 계정 바로 진입. 실제 로그인 미리보기는 접음 |
| 작성 탭 구경만으로 준비 시작 기록이 생김 | 준비 시작 버튼을 눌러야 작성과 체크 가능 |
| 비슷한 테스트 공고 2건으로 흐름 비교가 어려움 | 4개 묶음 12건. 조건, 마감, 제출 방식과 게시 상태 다양화 |
| 검색과 정렬이 제한됨 | 학생 묶음/마감/정렬, 담당자 상태/분류/검색/정렬 |
| 새로고침마다 테스트 계정을 다시 고름 | 같은 탭의 계정 유지. 종료 시 계정 기억 제거 |
| 공고의 제출 요구사항 변경을 학생이 확인할 수 없음 | 최신 요구사항과 이전 작성본을 함께 보존. 변경 확인 후 자기보고 |
| 가상 원문과 신청 링크가 example.org로 이동 | 테스트 안내 표시. 경로 확인과 자기보고는 별도 기록 |
| 담당자 첫 화면에서 전체 현황을 볼 수 없음 | 기간/분모를 명시한 KPI, 일별 추이, 마감 일정, 공고 비교 |
| 편집 화면이 길어 저장 버튼을 찾기 어려움 | 단계 바로가기와 고정 저장 버튼. 모바일 첫 입력란과 저장 버튼 노출 |
| 게시된 공고를 임시저장하면 학생에게 안 보이는 효과가 모호함 | 게시 내리고 임시저장 문구와 확인 대화상자 |
| 모바일 메뉴를 닫기 어려움 | 배경 닫기와 Escape 지원 |

가상 시나리오와 브라우저 행동 기록은 분리했습니다. 수치로 이탈 원인을 추정하지 않습니다. 학생 지원서 본문과 개인별 민감정보를 대시보드에 제공하지 않습니다.

검증 명령은 README와 VERIFICATION을 참고하세요. 화면 캡처는 로컬 tmp/browser-checks에 보관하며 배포하지 않습니다.

## 추가 사용 검토: 수치 확인에서 공고 수정까지

같은 날짜에 학생과 담당자 화면을 다시 직접 사용했습니다.

| 재현한 불편 | 수정 |
|---|---|
| 대시보드 핵심 수치에서 공고별 비교로 이동할 수 없음 | 수치를 누르면 해당 지표 순으로 공고 비교를 정렬하고 이동 |
| 공고 비교표에서 수치를 확인할 공간 없이 편집 화면으로 이동 | 선택 공고의 기간, 분모, 5개 지표와 수정 버튼을 함께 표시 |
| 7일 집계에서 수정 후 복귀하면 14일로 초기화 | 집계 출처, 기간, 정렬, 선택 공고를 유지 |
| 개별 집계 화면에 수정 버튼이 없음 | 집계에서 바로 수정하고 이전 화면으로 복귀 |
| 검색 초기화 뒤에도 묶음 조건이 남음 | 검색어, 분류, 묶음, 마감 조건 함께 초기화 |
| 빈 신청 상태 탭에 안내가 없음 | 상태별 빈 안내와 전체 신청 보기 추가 |
| 관심 수집 공고 검색 결과와 표시 건수가 다름 | 수집 공고도 검색과 건수에 포함 |
| 관심 공고 본문을 닫으면 전체 보관함으로 이동 | 원래 관심 목록의 검색과 스크롤로 복귀 |

짧은 애니메이션은 그래프 표시, 선택 공고 펼치기, 준비율, 체크 상태, 모바일 메뉴와 저장 안내에만 적용했습니다. 수치를 보간하거나 천천히 증가시키지 않습니다. `prefers-reduced-motion`에서는 애니메이션과 부드러운 스크롤을 끕니다.
