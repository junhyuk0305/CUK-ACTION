# CUK ACTION 후속 작업 3개

기록일: 2026-11-11

## 현재 판단

기획안 전체 약 60%, 외부 연결 전 테스트 버전 약 85%. 기능과 검증 범위에 대한 당시 추정입니다. 공수 산정이나 합격률이 아닙니다. 이후 세션은 실제 코드와 검사 결과를 기준으로 다시 판단합니다.

현재 핵심 흐름: 공고 선택, 조건 확인, 직접 작성, 제출 준비, 제출 완료 자기보고, 후속 절차, 담당자 집계. 구현과 사용 방법은 [OFFLINE-WORKFLOW.md](OFFLINE-WORKFLOW.md)를 따릅니다.

마지막 검증 기록: 규칙 검사 19개, 로컬 PostgreSQL 권한 검사 22개, 브라우저 스크립트 6종, 빌드 통과. 신규 전체 흐름 검사의 외부 요청과 런타임 오류는 0건입니다. 기준 기록은 [VERIFICATION.md](VERIFICATION.md)와 `tmp/browser-checks/workflow-result.json`입니다. 새 세션에서 필요에 맞게 재검증해야 합니다.

현재 데이터: 수집 공고 901건, 기존 가상 공고 12건, 기존 시연 4건, 실제 공고 기반 흐름 테스트 초안 4건, 가상 학생 프로필 8종. 프로필 유형 8개와 계정 8개는 다릅니다. 학생 계정은 A/B입니다.

실제 공고 기반 테스트 초안은 첨부 내부까지 모두 검수한 실운영 공고가 아닙니다. 날짜와 접수 경로는 가상입니다.

## 남은 핵심 내용

| 영역 | 남은 일 |
|---|---|
| 실제 공고 | 유형별 10~15건 검수, 첨부 근거, 정답셋, 미확인 항목 분리 |
| 조건 비교 | 실제 사례에 필요한 복합 조건과 선택 항목별 자격 검증 |
| 사용자 검증 | 원문만 보는 과제와 서비스 사용 과제 비교, 정답률과 준비 시간 및 누락 측정 |
| 서버 운영 | 실제 인증, 서버 저장, 기기 간 동기화, 신규 기수별 집계와 후속 집계 RPC |
| AI 처리 | 본문과 첨부 추출, 원문 근거, 오류 검수, 실제 모델 평가 |
| 알림 운영 | 예약, 변경 감지, 중복 방지, 재시도, 실제 수신 확인 |
| 학교 연계 | 학적, 공식 접수, 선정, 참여, 수료 확인. 기관 협의가 필요한 확장 단계 |

연결 단계의 제안 순서: 서버 저장과 인증 → AI 공고 추출 → 카카오 알림. 학교 연계는 후속 확장. 이번 3개 작업에서는 연결하지 않습니다.

## 실행 순서와 충돌 방지

1번과 2번은 독립 세션에서 진행할 수 있습니다. 2번은 제품의 `src` 파일을 고치지 않습니다. 3번은 1번의 데이터 계약과 2번의 설계가 정리된 뒤 진행합니다.

같은 작업 폴더를 공유하면 세션 간 변경이 즉시 보입니다. 다른 세션의 변경을 되돌리지 않습니다. 기능과 UI가 만나는 `main.jsx`, `Manager.jsx`, `gateway.js`를 동시에 수정하지 않습니다. 착수 때 최신 파일 상태를 확인하고 담당 범위를 기록합니다.

이번 요청은 기록과 프롬프트 준비입니다. 새 채팅을 자동으로 만들거나 각 작업을 시작한 것은 아닙니다.

## 공통 제약

- Supabase, AI API, 카카오, 학교 시스템의 새 연결 금지. 발송과 외부 제출, 배포 금지.
- GitHub, 공식 문서, 공개 제품 화면의 읽기 전용 리서치는 허용. 서비스 런타임 외부 요청과 구분.
- 실제 학생 개인정보 수집 금지. 가상 학생 데이터 사용.
- 기존 작성본, 체크리스트, 관심 공고, 완료 자기보고 보존.
- 자격 충족, 준비 완료, 링크 이동, 자기보고, 공식 접수의 의미 유지.
- 개인정보와 지원서 본문을 담당자 집계에 노출하지 않음. 1~4명 비공개 유지.
- AI 대필과 자동 지원서 생성 제외.
- 현재와 과거 공고, 검수 사실과 가상 상황, 실행한 검사와 예정 검사를 구분.
- 기존 기능을 없애거나 검사를 약하게 바꿔 통과시키지 않음.
- 필요한 수정만 수행. 범용 프레임워크, 새 상태관리, 대규모 폴더 개편은 근거 없이 도입하지 않음.

## 인수인계 방법

각 세션은 담당 지시서를 읽고 시작합니다. 완료 시 지시서의 실행 기록을 갱신합니다. 변경 파일, 검증 결과, 한계, 다음 세션이 알아야 할 데이터 형식 변경을 남깁니다.

로컬 주소는 실행 중일 때만 유효합니다. 개발 서버가 계속 켜져 있다고 가정하지 않습니다. `package.json`과 현재 포트를 확인한 뒤 실행합니다.
