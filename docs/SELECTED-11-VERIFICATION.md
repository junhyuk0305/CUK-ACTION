## 운영 연결

브라우저에는 Supabase URL과 공개 키만 설정한다. 기존 마이그레이션에 이어 `supabase/migrations/202611160001_guides.sql`을 적용하고 `notice-guide` Edge Function을 배포한다. 함수가 사용하는 서비스 키와 `GEMINI_API_KEY`는 서버 비밀 설정에만 둔다. 모델은 `GEMINI_MODEL`로 바꿀 수 있고, 비워 두면 `gemini-3.5-flash-lite`를 쓴다. 운영 Supabase 로그인, 함수 배포, 실제 모델 응답은 이번 검증에 포함되지 않았다.

실제 조사 집계가 생기면 운영자가 개인정보 없는 출처명, 조사 기간, 전체 고유 응답자 수, 항목별 고유 응답자 수를 확인한 뒤 서버에서 아래와 같이 등록한다. 값은 SQL 매개변수로 바인딩한다. 같은 출처와 기간을 다시 등록하면 기존 행이 정정된다. 실자료가 없는 현재는 아무 행도 등록하지 않는다.

```sql
insert into public.notice_responses
  (notice_id,source,starts,ends,total,target,route,materials)
values ($1,$2,$3,$4,$5,$6,$7,$8)
on conflict (notice_id,source,starts,ends) do update set
  total=excluded.total,target=excluded.target,route=excluded.route,materials=excluded.materials;
```

브라우저는 원시 집계 테이블을 읽지 않는다. 공고별 RPC가 공개 가능 항목만 돌려준다. 1~4명 항목은 null이며 합계와 비율은 반환하지 않는다. 테스트 계정의 로컬 저장소는 운영 보안 경계가 아니다. 실서버 권한은 PostgreSQL 정책 및 함수 검사로 별도 검증했다.
