# 테스트 공고 묶음

모든 묶음 공고는 UI와 준비 흐름을 확인하기 위한 가상 자료입니다. 실제 모집이나 선발 결과를 뜻하지 않습니다. Supabase는 연결하지 않았습니다.

## 구성

가상 공고 12건을 4개 묶음으로 나눕니다. 담당자 A는 8건, 담당자 B는 4건을 관리합니다. 처음 생성할 때 게시 중 8건, 임시저장 2건, 게시 종료 2건이 있습니다.

| 묶음 | 공고 | 확인할 흐름 |
|---|---|---|
| 프로젝트와 공모전 | 학생 프로젝트 모집, 캠퍼스 아이디어 공모, 지역 문제 해결 리빙랩 | 여러 작성 문항, 팀 조건의 직접 확인, 임시저장 후 검수 |
| 장학과 생활 지원 | 학업 지속 장학금, 지역 거주 생활지원금, 성장 경험 장학 에세이 | 학점 미입력, 조건 미충족, 거주 기간과 별도 증빙, 종료 공고 집계 |
| 진로와 직무 경험 | 직무 탐색 오픈클래스, 현직자 포트폴리오 피드백, 겨울 직무 체험 프로그램 | 작성 문항 없는 신청, 포트폴리오 권한 확인, 마감 임박, 사전 질문 |
| 교류와 캠퍼스 활동 | 글로벌 버디 매칭, 캠퍼스 문화기획단, 국제교류 준비 워크숍 | 자기소개, 학년 조건, 활동 가능 시간, 후속 절차 |

마감은 처음 묶음을 생성한 한국 날짜를 기준으로 정합니다. 일부는 1~3일 뒤에 마감하고 일부는 모집이 종료된 상태입니다. 브라우저에 저장한 뒤에는 사용자가 수정한 마감과 내용을 자동으로 바꾸지 않습니다.

공식 접수 미연동입니다. 공고의 경로는 `example.org`를 사용하는 테스트 주소이며 실제 신청이나 파일 전송을 받지 않습니다. 근거 문구 역시 가상 모집 요강으로 표시합니다.

## 학생 확인 시나리오

1. 프로필을 비운 채 장학 공고를 엽니다. 학점과 거주 기간은 확인 필요로 표시됩니다.
2. 학점 2.8을 입력합니다. 평균 학점 3.0 조건만 미충족으로 바뀝니다.
3. 포트폴리오 피드백 공고를 엽니다. 3~4학년 조건과 별도 링크 권한 확인을 구분합니다.
4. 오픈클래스의 준비를 시작합니다. 별도 작성 문항 없이 일정과 신청 항목을 확인합니다.
5. 프로젝트 공고에 직접 작성하고 로그아웃합니다. 다시 같은 테스트 계정으로 들어가 이어서 작성합니다.

## 담당자 확인 시나리오

1. 통합 화면에서 게시 상태, 마감 임박 공고와 가상 시나리오 지표를 확인합니다.
2. 데이터 구분을 이 브라우저 기록으로 바꿉니다. 실제로 눌러 본 행동만 집계되는지 확인합니다.
3. 임시저장 공고의 근거와 신청 경로를 검수한 뒤 게시합니다.
4. 학생 계정으로 게시 공고에서 준비를 시작합니다. 담당자 집계에서 해당 행동을 확인합니다.
5. 담당자 B로 바꿔 자신의 공고만 관리 화면에 표시되는지 확인합니다.

## 통합 그래프의 수치

가상 시나리오는 브라우저 묶음 생성일을 끝으로 하는 30일간의 합성 활동입니다. 동일한 기준일이면 같은 숫자가 나옵니다. 실제 학생 정보와 지원서 본문은 포함하지 않습니다.

가상 시나리오와 이 브라우저 기록은 함께 더하지 않습니다. 가상 이벤트는 `events` 저장소에 쓰지 않습니다. 사용자가 새로 만든 공고에는 가상 이벤트를 붙이지 않습니다.

- 통합 지표: 선택 기간의 담당 공고 전체에서 중복을 제거한 고유 학생 수
- 일별 그래프: 해당 날짜의 고유 학생 수. 날짜별 수를 더하면 기간 전체 고유 인원과 다를 수 있음
- 공고별 비교: 해당 공고의 고유 학생 수. 한 학생이 여러 공고를 보면 행별 수의 합이 통합 지표보다 클 수 있음
- 분모: 같은 기간 담당 공고를 상세 조회한 고유 학생 수
- 소수 제한: 1~4명은 통합, 일별, 공고별 모두 비공개. 0명은 0으로 표시
- 제출 완료: 학생의 자기보고. 신청 링크 이동과 공식 접수 완료를 뜻하지 않음

가상 시나리오에서 관심과 준비가 적다는 이유만으로 중도 포기 원인을 추정하지 않습니다.

## 기존 데이터 보존

`cuk-action-test-v2` 저장소를 유지합니다. `fixtureVersion: 3`으로 한 번만 갱신하면서 없는 기본 공고를 추가합니다. 기존 공고의 제목, 마감, 문항과 학생 작성 내용, 기존 행동 기록은 덮어쓰지 않습니다. 기존 기본 공고 2개의 ID와 제목은 유지합니다.

규칙 검증: `node --test src/fixtures.test.js`. 브라우저 역할 구분은 실제 서버 접근 통제 검증을 대신하지 않습니다.
